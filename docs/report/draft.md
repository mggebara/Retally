## 1. Summary

We built a benchmark that asks a language-model system to reproduce the headline numbers of published economics and political-science papers, scored against the papers' printed values and against the values that human replicators at the Institute for Replication (I4R) obtained.  Each paper is attempted in three modes: *seeded* (the authors' replication scripts are provided), *independent* (scripts withheld, target values shown) and *blind* (scripts and target values withheld).  Two systems sat the benchmark: a fixed pipeline that writes one R script and refines it, and a Claude Code agent with its own loop.  On twenty-three evaluation papers (278 pinned claims) the agent reproduced 277, 267 and 250 claims within tolerance of the paper's printed value in seeded, independent and blind mode; the pipeline, run on the same model family, reproduced 263, 235 and 170.  Those are first samples.  Second samples of both systems now exist on all twenty-three papers: the agent's second reproduced 270 and 248 in independent and blind mode (it was not rerun seeded), and the pipeline's second 265, 223 and 172 in a complete second sample.  On the seventeen papers measured first (201 claims) the agent reproduced 200, 194 and 180, then 194 and 177, and the pipeline 194, 169 and 118, then 195, 161 and 120.  On the seven papers where an older model was also run, moving the pipeline from `claude-opus-4-7` to Opus 5.5 raised its blind count from 24 to 51 of 79, against the agent's 75.  The finding: with the authors' code in hand both systems are near the ceiling, and the loss when the code and the targets are withheld is mostly a property of the harness and of what the papers' methods sections leave unstated.  Over the twenty-three papers the first-sample gap is 14 claims seeded, 32 independent and 80 blind; on the six papers added last it is 8, 7 and 18, the seeded figure driven by one pipeline cell (Section 4.3).  Pairing each of the agent's two samples with each of the pipeline's, the gap over all twenty-three papers is 32 to 47 claims in independent mode and 76 to 80 in blind mode (25 to 33 and 57 to 62 on the seventeen measured first, 18 to 20 and 40 to 53 on the thirteen); the seeded difference, against the agent's one seeded sample, is 12 or 14, more than half of it one inverted pipeline cell, Douenne seeded (Section 4.3), and 5 or 6 on the seventeen.  A memorization probe, asking the same model for each number from memory with no data, landed 41 of the 278 claims inside the blind tolerance, none by stated recall, so memory does not explain the agent's blind result.  The limitations: the pipeline on Opus 5.5 has two samples per cell on all twenty-three papers, the agent two in independent and blind mode and one in seeded, and the older pipeline one; all twenty-three papers predate the models' training cutoffs; two samples show how much a cell moves but do not give a standard error, so none of these differences carries a measured uncertainty.

## 2. Introduction

A replication package is a set of data files and the scripts that turn them into the paper's tables.  Re-running the scripts and checking that the printed numbers come out is *computational reproduction*.  It confirms that the package is complete and that the code does what the tables say, but the specification (which sample, which controls, which estimator, which standard errors) travels inside the scripts.  A replicator who rebuilds the analysis from the paper's text and the raw data, without the authors' code, performs a different test: whether the paper describes its own analysis well enough to be redone.  We call that *independent reproduction*.  A third variant withholds the printed results as well, so that the replicator cannot steer toward the known answer.  We call that *blind reproduction*.

The three are routinely reported under one word.  "The model reproduced the paper" can mean that it translated a Stata do-file into R, that it rebuilt the regression from the methods section while knowing the target coefficient, or that it derived the coefficient without ever seeing it.  These are different claims about the model and different claims about the paper.  This benchmark keeps them apart: every result row records its mode, and no number in this report pools two modes.

The ground truth comes from the Institute for Replication (I4R), which organizes replication games in which teams of economists and political scientists reproduce recently published papers and file reports.  I4R's first meta-database covers 110 replication reports on 109 papers from leading economics and political-science journals, with estimate-level rows that record both the paper's coefficient and the replicator's (`benchmark/corpus/SOURCE.md`).  It is the only source we know of that gives, for each paper, a human replicator's number to set beside the published one.  That matters for two of our papers, where the replicators found that the published numbers are wrong.

Two systems were evaluated.  The *pipeline* is a fixed program: it extracts the paper's text and a methodology summary, writes one R script with a language model, runs it in a sandbox, repairs it when it crashes (an *error refinement*), and, when the target values are shown, tells the model which claims are off and by how much and asks for a corrected script (a *claim refinement*), with at most three of each.  The *agent* is a Claude Code session given the same task text, the same data mount and the same sandbox, and left to run its own loop: it can inspect the data, run exploratory scripts, read the whole paper and try alternatives.  Both are scored by the same harness from the numbers their final script prints.  The question the comparison answers is how much of what looks like a model's reproduction ability is the loop around it.

"Original software" is the language of the authors' package.  Every reproduction, whatever the original, is written in R and run in an R sandbox; Stata originals are in scope because the seeded prompt can show the do-file and because the claims can be checked without running Stata.  "I4R values" counts the pinned claims for which the replicators recorded their own number.  The I4R outcome label is the meta-database's verdict mapped onto the catalog schema; papers I4R rated "minor discrepancies" carry the label `reproducible` here.  Forsythe is labeled `robust`, not `reproducible`, because I4R rebuilt its data from IPUMS rather than running the package.  Douenne is the third `not_reproducible` paper, after Montero and Holman.

### 3.2 Pinned claims

A *pinned claim* is one published number that the benchmark scores: a coefficient, a standard error, a test statistic or a sample size, stored with its printed value, its standard error where the paper gives one, a location ("Table 1, column 2") and a short description of what it is.  The curation rule (`benchmark/README.md`, "Curating headline claims") admits a number only if it is in the abstract or a main results table, the paper's conclusions rest on it, and it is stated numerically; the target is eight to twelve claims per paper.  The evaluation papers carry 278 pinned claims (154 on the thirteen measured first, 201 on the first seventeen), the dev papers 35.  One exception to the main-table rule is recorded: Bokobza's main text has only coefficient plots, so its claims come from the online-appendix tables that print them.

Each claim also has a *context* string, written in the paper's own words, which every mode shows to the reproducer.  Two curation rules came out of leaks found during the project.  Contexts may not name package variables, file names or commands (ROADMAP 1.7, where the first contexts had been written from the package), and no context may state the value of any pinned claim of its entry, which a catalog test now enforces (ROADMAP 3.4, PR #69).

### 3.3 Three modes

The modes differ only in what the reproducer is shown.

| Mode | Authors' scripts | Script-free data copy | Claim values and SEs | Claim refinement loop | What a pass measures |
|---|---|---|---|---|---|
| seeded | shown, as ground truth | no (full package) | shown | on | translating the authors' code |
| independent | withheld | yes | shown | on | rebuilding the analysis from the text, knowing the targets |
| blind | withheld | yes | withheld (also redacted from the paper text) | off | deriving the numbers without seeing them |

In independent and blind mode the data directory is a *script-free copy*: scripts are removed by file name, and logs, transcripts, code saved under other names and generated regression tables are removed by content (`benchmark/README.md`, "The script-free copy").  Blind mode additionally redacts every pinned value and standard error from the paper text, including percentage forms such as "3.5 points" for 0.035.  A blind pass is therefore the only count free of *target-guided search*, by which we mean changing the analysis until the printed number appears.

### 3.4 Tolerance and scoring

A claim *passes* when the reproduced value is within tolerance of the paper's printed value.  We report these as counts of claims, not as rates.  Seeded mode uses a strict relative band per claim type (2 % for coefficients, 5 % for standard errors, 1 % for other quantities such as sample sizes; `benchmark/README.md` and `src/retally/validation/comparator.py`), because translating the authors' code should land on their numbers.  Independent and blind mode accept a value within one standard error of the printed value when the claim pins a standard error, never narrower than the relative band, and use the relative band otherwise; rebuilding a specification from prose is not expected to hit the fourth decimal.  In every mode the band is never narrower than half a unit in the printed value's last decimal place, so a reproduction that rounds to the printed number always passes.  This floor matters for papers that print coefficients to one significant digit.

The wider independent band is a real asymmetry.  A pass count in independent mode is not comparable with one in seeded mode on closeness, so we report median relative error and the share of claims within one, two and five times their tolerance beside every count (Section 4.6).

Scoring belongs to the harness, not the reproducer.  The reproducer returns raw `name = value` pairs printed by its final script; the harness matches them to the pinned claims and applies the mode's tolerance.  Three verdicts are recorded per paper and never collapsed into one: `retally_ran` (the reproducer finished), `agrees_with_paper` (every pinned claim within tolerance of the printed value) and `agrees_with_i4r` (every claim for which I4R recorded a value, and for which the reproducer printed a value, within tolerance of the *replicator's* value).  A reproduction that matches the paper but not the replicators is the case the benchmark exists to surface.

Each row also records a *first-scored* count: the claims passed by the first execution that printed a parsable result, after any crash repairs and before any claim-targeted feedback.  The difference between first scored and final is what target-guided refinement added.

### 3.5 The `Reproducer` protocol and the two reproducers

The harness talks to a reproducer through one method, `reproduce(paper_source, language, dataset_reference, claims, reproduction_mode)`, which returns a `Reproduction`: the raw outputs keyed by claim name, the generated code, its output and exit code, declared deviations and per-stage flags, and no verdicts (`benchmark/reproducer.py`).  The pipeline is the reference implementation.  The agent is plugged in through a file-system reproducer: a rendering step writes a task directory (the pipeline generator's own claims block, dataset listing and mode instructions, the paper text, and the mode's data mount), a Claude Code subagent does the task and writes its scripts, outputs and a manifest, and the harness scores the files (ROADMAP 3.3).  The harness never drives the agent and never calls the API for it.

The agent's isolation is partly by instruction.  Its task directory holds only the mode's mount, and the sandbox mounts nothing else, but the session runs inside a checkout of this repository, where the catalog (with pinned values) and the download cache (with the authors' scripts) are readable.  Each agent had to list every file it read outside its mount; across the runs reported here the lists were empty or named only the task's own files (ROADMAP 3.3).

### 3.6 Models

Three model configurations appear, and the report never pools them.  The pipeline's original rows ran on `claude-opus-4-7` with no extended thinking (ROADMAP 3.5).  The pipeline was then moved to `claude-opus-5-5` through the API, with effort `high` for code generation and refinement and `medium` for claim extraction (`src/retally/llm.py`); credit allowed four of the seven earlier evaluation papers.  The agent rows, and the oracle rows below, ran on the Claude desktop app's Opus model at its default effort; the agents reported it as Opus 5.5.

### 3.7 The LLM oracle

The *oracle* runs the pipeline with every Claude call answered out of band rather than by the API (`src/retally/llm_oracle.py`, ROADMAP 3.5).  The pipeline's requests are built exactly as for a live run; each unanswered one is written to disk, a Claude Code subagent told to use no tools and read nothing but the prompt writes the answer, the answer is installed, and the run resumes.  It guarantees that the prompts, the loop and the scoring are the pipeline's own, that oracle answers live in a separate cache and can never be served to a real API run, and that oracle rows carry their own label.  It does not guarantee that the answerer thinks at the effort the request names (the subagents run at the desktop default), and it does not enforce isolation: two of 88 answering subagents reported running a harmless shell command on their own answer file, and none reported reading anything outside the prompt (ROADMAP 3.5).  The oracle let us run the remaining nine evaluation papers, and later the four of ROADMAP 3.6 and the six of ROADMAP 3.7, through the pipeline at no API cost.

### 3.8 Sandbox and cost accounting

Every script, from either reproducer, runs in the same Docker image (`retally-sandbox-r`, 47 R packages plus base; ROADMAP 1.8) with no network, a read-only file system and the pipeline executor's limits of 300 seconds, 4 GB and one CPU (ROADMAP 3.3).  Pipeline rows record the tokens each API call used, by model, and an estimated cost from one price table (`benchmark/pricing.py`).  Agent and oracle rows use plan usage, which the results files do not price.

### 4.1 The pipeline on `claude-opus-4-7`

On the seven evaluation papers measured first, the pipeline on `claude-opus-4-7` reproduced 55 of 79 claims seeded, 41 independent and 24 blind.  Its first-scored counts were 46, 27 and 24.  Seeded was not a ceiling.  Grier failed in every mode, including seeded, because the model estimated a conditional logit instead of the paper's logit with fixed-effect dummies, and Arias passed only its four counts seeded because the model re-estimated the conjoint effects with a linear model instead of translating the package's `cjoint::amce` call (ROADMAP 3.2).  Montero is the clearest single case.  I4R found duplicated rows behind the paper's Table 5 earnings results.  Seeded, the first script matched neither the paper nor the replicators; one claim-refinement round, told the gaps to the printed values, then reproduced the paper's printed numbers exactly.  Target-guided search converged on numbers the replicators had shown to be wrong (ROADMAP 3.2).

### 4.2 The agent on twenty-three papers

Over all twenty-three evaluation papers the agent reproduced 277, 267 and 250 of 278 claims seeded, independent and blind, with first-scored counts of 267, 252 and 243.  On the seventeen papers of ROADMAP 3.2–3.6 it reproduced 200, 194 and 180 of 201 (first scored 194, 192 and 173), on the thirteen measured first 153, 148 and 135 of 154, on the six added last 77, 73 and 70 of 77, and on the seven papers above 78, 78 and 75 of 79.  Its misses are few and concentrated: in independent mode eleven claims on five papers, in blind mode twenty-eight on eight (Section 5). This decomposition should not be leaned on hard, for three reasons. The route split shows the consequence: almost all of the seven-paper harness effect comes from the API route (10 claims independent, 23 blind), while on the three oracle-route papers it is one claim in each of those modes.  Second, the two halves of "pipeline on Opus 5.5" are not the same answerer: the API rows run at named effort levels, the oracle rows at the desktop default.  Third, the decomposition uses the first pipeline sample only, and the agent and the 4.7 pipeline have one sample per cell.  The second samples (Section 4.8) put the seventeen-paper harness gap at 25 to 33 claims in independent mode and 57 to 62 in blind mode, but they move single pipeline cells by up to six claims, which is larger than the one-claim harness effects on the oracle route.  None of these differences has a standard error, and we make no claim of statistical significance for any of them.

The seeded Forsythe rows of both systems show the reverse, paper ✓ and I4R ✗, as expected: I4R rebuilt Forsythe's panel from IPUMS and reports a different sample, so its numbers are not the package's.

The papers I4R rated not reproducible tell the more useful story.  On Montero, every configuration in seeded mode reproduced the paper's printed numbers, which the replicators showed are produced by duplicated rows; the seeded agent did so on its first script by following the do-file's "replicating original results" block (ROADMAP 3.3).  Seeded reproduction faithfully reproduces a package's error.  Independent and blind agents built a paper-faithful specification that matched neither the paper (except inside the wide band) nor the replicators.  Holman shows the same pattern: seeded runs follow the do-file, which estimates random effects and a linear model where the paper says fixed effects and a logit, and reproduce the printed numbers that I4R's report (DP41) corrected; the blind agent did what the paper says and reproduced neither (ROADMAP 3.4). Here independent mode agrees with the paper too, inside the one-standard-error band, for both systems.  Hollyer shows the band's other face: the seeded rows of both systems match the paper and miss four of the replicators' values, including the two extremist-party rows where the paper's text and the authors' code disagree, while every independent row, and the agent's blind row, passes those two claims against both the paper and the replicators, because one standard error is wide enough to cover the gap between them (ROADMAP 3.7).

## 5. Failure taxonomy

We classified every claim that missed in independent or blind mode on the evaluation papers, for the pipeline on `claude-opus-4-7` (seven papers), the pipeline on Opus 5.5 (twenty-three papers: API rows where they exist, oracle rows otherwise) and the agent (twenty-three papers), first samples only.  The classification rests on the per-paper analyses in ROADMAP 3.2–3.7 and the claimed and reproduced values in the results files; each rule, with the passage it relies on, is in `TAXONOMY_RULES` in `docs/report/tables.py`, and the per-claim list is in `docs/report/tables/taxonomy_claims.md`. **Data-file resolution.**  The reproducer read the wrong file.  On Montero blind the pipeline on Opus 5.5 built its regression on 130 rows instead of 4,770 because it never found the right data file without the scripts (ROADMAP 3.5).  On Grier the package ships three datasets that differ only in the contribution window and never says which is which; ROADMAP 3.5 attributes the pipeline's independent run, on 172 and 94 observations instead of 186 and 106, to these files, while the agent resolved the ambiguity by trying both (ROADMAP 3.4–3.5).  We keep that classification because it is ROADMAP's, but it is weaker than the Montero case.  In both pipeline samples the three contribution-window claims carry one identical value, so the pipeline never estimated the windows separately, and in the second sample the independent run reached 186 and 106 observations and still missed every coefficient (appendix table "Grier and Holman, claim by claim").  If the data file is the cause, it is in the form "one file used for all six models", not the mapping between the two window files that the agent faced.  Every miss in this category belongs to the pipeline.

**Specification mismatch.**  The reproducer estimated a different model from the one the paper states.  The pipeline on `claude-opus-4-7` produced every Adams blind coefficient with the wrong sign (ROADMAP 3.2).  The agent's six specification misses are all Gagliarducci blind: it used the dataset's percent-opposite variable, which is missing for bills with no cosponsors, where the paper divides by cosponsors plus one, so Panel B lost bills and its coefficients moved (ROADMAP 3.4).  The oracle pipeline's twelve on Mokyr blind are variable construction: per-capita densities built on a different population column, so the coefficients came out about 10,000 times the printed values (ROADMAP 3.7).

*Holman is not counted here, and why.*  ROADMAP 3.5 describes the oracle pipeline's Holman independent and blind runs as fitting "random-effects / linear probability models where the paper uses fixed effects and logit".  That cannot explain a miss.  Random effects and a linear model are what the authors' do-file estimates (ROADMAP 3.4), and that specification is what reproduces the printed Table 2 in seeded mode, for the pipeline and the agent alike.  The results files point to the sample instead.  In each pipeline row that misses Table 2, the two Table 2 sample sizes are wrong too: 145,012 and 86,517 against 143,499 and 97,155 in the first independent sample, and 239,919 and 1,481,392 in blind mode in both samples, where two of the "May best PM" coefficients come out numerically zero. **Sample restriction.**  The model was right and the sample was not.  The oracle pipeline ran Altmann blind on 17,840 observations instead of 12,160 by taking the wrong subset of treatment arms, and Acemoglu blind on 178 and 171 clusters instead of 181 and 175 (ROADMAP 3.5). **SE or cluster choice.**  No evaluation-paper miss in independent or blind mode was attributed to the standard-error or clustering choice. **Tolerance artifact.**  One miss. **Under-specified methods section.**  The paper's text does not determine the number, or states a rule the authors' code does not follow, so a reproducer that follows the text misses and the seeded run, following the code, does not.  This is the category the benchmark exists to measure, and it accounts for 24 of the agent's 39 misses.  López-Moctezuma's four attitude-index effects fail in independent and blind mode for both harnesses because the paper does not state the attendance weights or the item orientations (ROADMAP 3.4).  Adams states that both parties need at least four MPs; the authors filtered on one party only, and the blind agent, applying the stated rule twice, got 1,535 dyads against 1,842 both times (ROADMAP 3.3–3.4).  Montero's paper states a five-member rule its code never applied (ROADMAP 3.2), and Holman's states fixed effects and a logit where its code uses random effects and a linear model (ROADMAP 3.4).  Grier's deflator base year is unstated; two agent runs chose different years, which rescales every contribution coefficient by 8 % (ROADMAP 3.3).  Labandeira adds two cases (ROADMAP 3.7).  Its paper says every Table 2 column has quarterly dummies, and the authors' instrumental-variable columns have none, so a text-following column 2 misses in both agent rows.  And its paper does not say the price regressor is a real (deflated) price: the blind agent, and the blind pipeline, built price as expenditure over quantity, which makes every expenditure coefficient identical to its consumption counterpart, and missed the expenditure columns.

**Unclassified.**  Seventy-nine misses, seventy-two of them the pipeline's, have no cause in ROADMAP that the results files bear out. **Not a miss: the sandbox's input limit.**  One failure mode cost no claims but shaped how two papers were reproduced.  The sandbox gives every script 300 seconds against a read-only mount, and the agents measured that mount at roughly 5 to 15 MB/s.  Hanushek's Table 1 file is 2.47 GB as `.dta` and 2.97 GB as `.csv`. All three still passed every Table 1 claim. The files do not say why the first-sample agents' reads timed out. Forsythe's 2.17 GB file met the same constraint (ROADMAP 3.6), and every agent there read a column subset.  During the agent batch of ROADMAP 3.7 the Docker daemon also went down twice. **The oracle is not the API.**  Oracle answers come from desktop subagents at default effort, not at the effort the pipeline's request names; isolation is by instruction; and the extraction prompts truncate the paper text by design, which several answering agents noted (ROADMAP 3.5).  We present oracle rows beside the API rows, labeled, and never pool them in a table. **Few runs per cell.**  The pipeline on Opus 5.5 has two samples per cell on all twenty-three papers; the agent has two in independent and blind mode on all twenty-three (three in five blind cells) and one in seeded mode; the pipeline on `claude-opus-4-7` has one on the evaluation papers. **Scope.**  Every reproduction is written in R.  Stata originals are included only because their claims can be scored without running Stata. **Seeded mode reproduces the package's mistakes.**  Montero seeded passes every claim on every configuration, and the numbers it reproduces are wrong (Section 4.7).  A seeded pass certifies the package, not the paper's result.

## 7. Using the benchmark with another agent

Any system that implements the `Reproducer` protocol can be scored on the same catalog without changing the harness.  It receives the paper source, the target language, a reference to the dataset, the pinned claims and the mode, and returns raw outputs keyed by claim name plus its code and logs.  The harness, not the agent, applies the tolerance and records the three verdicts, so no reproducer can grade its own exam or narrow the claim set.  An adapter must honor the mode by what is on disk (the script-free copy in independent and blind mode, not an instruction alone), run its code in the same network-less sandbox image, and raise rather than return junk when it cannot produce a result (`benchmark/README.md`, "Plugging in another agent").  A reproducer is registered by name in `benchmark/runner.py` or passed as `module:factory` on the command line.

The agent in this report used the file-system route: render a task per cell, let the agent work, score the files it leaves.  That route needs no code changes for a new agent, only a session that follows `task.md`.  The I4R meta-database the catalog draws on is MIT-licensed (`benchmark/corpus/SOURCE.md`).  The repository itself carries no license file, so the license of the catalog, the pinned claims and the harness is currently unstated.

> **Editor's note:** Choose a license before release (for example MIT or Apache-2.0 for code, CC BY 4.0 for the catalog and pinned claims).  The report should state it here.
>
> *Recommended resolution:* Pick a code license and a separate data license for the catalog and pinned claims before release, and state both here; a split like the example above is the common pattern for benchmark repositories.  The choice is the user's and this pass does not make it.

## 8. Next steps

Four pieces of work would most change what this report can claim.  A full variance pass, three runs per paper per mode on a frozen and tagged harness, would let the gaps carry uncertainty.  Part of it exists: the pipeline on Opus 5.5 has two samples on all twenty-three papers, and the agent two in independent and blind mode (Section 4.8).  What is missing is a second agent sample in seeded mode, a third sample for both systems, and an API-route second sample for the four papers whose two pipeline samples came by different routes.  Corpus growth to the 20–30 papers the roadmap targets, with the open-data and open-PDF funnel recorded, would make the per-category counts in Section 5 mean something; the corpus is at twenty-three, and the third shortlist pass found the open pool exhausted: the next growth needs the 33 openICPSR packages placed by hand under a user's login, which is the user's decision (Section 3.1.1).  A small set of post-cutoff replications, if I4R publishes them in machine-readable form, would give the contamination control that the memorization probe (Section 6) cannot (ROADMAP Phase 5 treats it as a bonus that expires with the next model release).
